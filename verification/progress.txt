## Iteration 1 (US-001 → US-004 verified on device)

### Build artifacts
- Built rootful + rootless .deb at versions 0.1.1 and 0.1.2. The 0.1.2 build is the one that produced visible touches on-device.
- Reason for 0.1.2: same-version dpkg -i (0.1.1 over 0.1.1) did NOT cause palera1n's TweakInject to re-inject the new dylib into SpringBoard PID 10788. Bumping to 0.1.2 forced a real package upgrade, after which all UIKit processes loaded the fresh dylib.
- Linker emits a benign `ld: warning: -multiply_defined is obsolete` — not a deprecated-API warning, ignored per AC-6.

### Symbol verification (US-001 AC)
- `xcrun dyld_info -exports .theos/obj/TouchSimulator.dylib` lists `__Z13simulateTouchiff` and `__Z22simulateTouchHandResetv` (C++-mangled) on both arm64 and arm64e slices. `nm -gU` had returned empty earlier because of the mangling — substantively the symbols are exported.

### Device platform notes (palera1n rootful)
- The tweak gets installed by dpkg into `/Library/MobileSubstrate/DynamicLibraries/TouchSimulator.dylib` but **palera1n loads it from `/usr/lib/TweakInject/TouchSimulator.dylib`**. lsof on SpringBoard confirms `txt REG ... /usr/lib/TweakInject/TouchSimulator.dylib`. Some trigger or symlink keeps the two locations in sync — sizes and SHA-256 match across both paths post-install. Document this in DEMO.md so future maintainers don't chase the wrong path.
- Choicy (a tweak loader gate) emits `Checking whether TouchSimulator.dylib should be loaded... ✅ (allowed)` per process. Verified for SpringBoard, assistivetouchd, PosterBoard, GradientPosterExtension, ExtragalacticPoster, CollectionsPoster, PhotosPosterProvider, EmojiPosterExtension, WeatherPoster.

### iOS 16.7.12 hardening verification (US-003 + US-004)
- All four DEBUG probe lines fired in SpringBoard (PID 10707, first respring) and assistivetouchd (PID 10708): `_enqueueHIDEvent present=1`, `_contextId present=1`, `BKSHIDEventSetDigitizerInfo present=1`, `senderID=0x200000000000060`.
- senderID `0x200000000000060` is the real IORegistry-discovered Multitouch ID on this device (NOT the placeholder), confirming `discoverSenderID()` succeeded.
- Sandboxed wallpaper extensions (PosterBoard, PhotosPosterProvider, etc.) correctly fall back to placeholder `0xDEFACEDBEEFFECE5` and hit the no-key-window safe path — exactly the behavior the hardening's nil-window guard is designed to produce.
- `simulateTouchHandReset()` survived without crash in every process where Example.xm exercised it.
- SpringBoard PID stable across 35s observation window post-respring (no crashes).
- No `dlopen|dyld|unrecognized selector` lines in the captured syslog referencing TouchSimulator.

### Demo trigger redesign (US-004 visible touch)
- The original Example.xm fired a 4-second `dispatch_after` timer in `%ctor`. On a respring, that timer expires DURING SpringBoard's lock-screen launch — the user unlocks AFTER and never sees the touch.
- Rewrote Example.xm to register a `UIApplicationDidBecomeActiveNotification` observer 1s after ctor; on each scene activation, runs a smooth 10-step swipe from (150,300) to (150,700) over ~330ms, followed by `simulateTouchHandReset()`. This fires every time any UIKit app comes to foreground — visible to the user during normal navigation.
- User confirmed visible touch in the Photos app on iPhone X iOS 16.7.12: "It's working! When I open the photo's app it works".

### Idiosyncrasies of palera1n rootful for future contributors
- idevicesyslog over network (`-n` with UDID) drops its lockdownd connection during SpringBoard respring; restart it after each respring to capture new SB activity.
- `log` command is not present at `/usr/bin/log`. `idevicesyslog` from the host Mac is the only path for unified logging capture without device-side tooling.
- The phone's SSH `mobile` user uses zsh, which does not expand the `[X]` glob trick used in macOS scripts (`ps -A | grep [S]pringBoard`). Use `bash -c "..."` or `grep SpringBoard | grep -v grep` instead.

## Iteration 2 (codex critic feedback addressed)

Codex returned REJECT on the first review with six must-fix items. Addressed in commit `1ecd3b1`:

1. Evidence files were only under `.omc/` (gitignored). Added tracked `verification/` directory holding this file plus `verification/syslog-excerpts.log`. DEMO.md gained an inline "Evidence captured during initial verification" section quoting the key probe / Choicy / safe-path lines.
2. Demo could miss activation when injection happened into an already-foreground process. Example.xm now registers the observer immediately on the main queue from %ctor and fires once with trigger label `already-active-at-inject` if `UIApplicationStateActive` is already true.
3. DEMO.md's expected log lines / coordinates did not match the code (`(100,100)→(100,300)` vs the code's `(150,300)→(150,700)`). DEMO.md synced to the actual code.
4. DEMO.md missed the dpkg-vs-TweakInject path detail. Added a dedicated section.
5. Example.xm blocked the main queue ~300 ms per activation via `usleep(30000) × 10` inside a single dispatch_after block. Replaced with a per-step `dispatch_after` chain on the main queue at +30/+60/.../+330 ms; main queue is no longer blocked for the demo.
6. senderID fallback was undocumented. Expanded the comment in `discoverSenderID()` and added a "senderID policy" section to DEMO.md.

Bumped version 0.1.2 → 0.1.3 because TweakInject's per-tweak load cache may not refresh on a same-version `dpkg -i` (same root cause as the 0.1.1 → 0.1.2 bump).

Codex re-reviewed the three-commit stack and returned **APPROVE**. Final shipped version is 0.1.3.
